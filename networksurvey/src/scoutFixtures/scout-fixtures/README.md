# NS Scout wire fixtures

Copied unchanged from `network-survey-esp32/test/fixtures/{proto,framing}` at commit `dc581b7`
(the fixtures last changed in `be97045`). The firmware's nanopb host tests produce them
(`test/host/proto_roundtrip/` and `test/host/link/`), so the app decodes exactly what a board sends.
After a protocol change, copy both folders again and rerun the Scout unit tests.

This folder is a source directory of two source sets (see `networksurvey/build.gradle`):
unit test resources, read by the decoder tests, and debug assets, read by the debug-only fake
Scout transport. Release builds never contain it.

`proto/` holds single messages (not framed): one `RecordBatch` per `record_*.bin`, plus
`BoardInfo`, `BoardStatus`, `ControlRequest` (Hello, Configure), `ControlResponse` (Hello),
`RawFrame` and `OtaAck`. Their field values are listed in the firmware's
`test/host/proto_roundtrip/main.c`.

## Framing fixtures

Notification payloads (the bytes after the ATT header) produced by the
firmware's C framing code in `firmware/components/link/link_frame.c`. They let
a phone-side decoder check that it reads board frames correctly
(`docs/protocol.md` section 4). Each file is one notification.

Generated by the host test in `test/host/link/` (`make -C test/host/link
fixtures`); `make -C test/host` checks them. Record messages come from the
single-record batches in `../proto/record_*.bin`, re-encoded as `Record`.

| File | Characteristic | Sequence | Bytes | Content |
|---|---|---|---|---|
| `control_ping_response_seq0.bin` | Control | 0 | 20 | One `ControlResponse`: `request_id` 5, OK, `PingResult` (nonce 1, `board_time_ms` 1767225600123, synced). Same bytes as the protocol.md example. |
| `ota_ack_seq258.bin` | OTA | 258 | 8 | One `OtaAck`: `next_offset` 4096, OK. Same bytes as the protocol.md example. |
| `status_two_messages_seq7.bin` | Status | 7 | 106 | Two copies of `../proto/board_status.bin` in one frame. |
| `records_mtu185_frame0.bin` | Records | 65535 | 159 | `RecordBatch` (synced): ap, client. |
| `records_mtu185_frame1.bin` | Records | 0 | 149 | `RecordBatch` (synced): probe, ble. The sequence wrapped; no gap. |
| `records_mtu185_frame2.bin` | Records | 1 | 65 | `RecordBatch` (synced): gps. |
| `records_mtu517_seq9.bin` | Records | 9 | 360 | `RecordBatch` (not synced): ap, client, probe, ble, gps. Two-byte batch length. |
| `records_exact_fit_mtu185_seq42.bin` | Records | 42 | 182 | `RecordBatch` (synced) with one 173-byte ap record (the largest that fits at MTU 185): exactly `ATT_MTU - 3` bytes. |

The three `records_mtu185_frame*` files are the frames the board sends for the
five records in order at MTU 185, so they also show packing and sequence wrap.
